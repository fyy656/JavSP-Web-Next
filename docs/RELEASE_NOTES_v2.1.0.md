# JavSP WEB v2.1.0

媒体库体验与稳定性的集中升级。新增批量刮削与失败重试，重写分类浏览与数据统计，统一 NFO 归属，并修掉一批会导致索引错乱的缺陷。

## 新增

- **媒体库批量刮削**：工具栏新增「批量刮削」，直接按当前筛选范围（媒体库 / 文件夹 / 状态 / 搜索 / 分类）把影片一次性加入队列，可先选「未刮削」「缺资料」再批量下发。已在队列中的影片自动跳过。
- **失败重试**：任务卡片为失败任务提供「重新刮削」按钮；手动刮削工具栏新增「重试失败」，一次把所有失败任务重新派发（同样跳过队列中已有的影片）。
- **资料按钮**：任务卡片与媒体库卡片统一使用「资料」入口，直接打开影片资料对话框；改完番号后可以「保存」而不刮削，再回列表批量刮削。
- **打开文件所在目录**：详情页可一键在资源管理器定位文件；超长路径自动改用 8.3 短路径，窗口会主动置顶。
- **任务记录看板**：概览页改为使用看板，展示任务记录、运行结果与日志入口，不再混入媒体墙；隐私模式开关迁到媒体库工具栏。
- **全部影片**：媒体库标签栏最前面新增跨库汇总的「全部影片」，支持统一搜索、排序与分类浏览。
- **维护工具**：新增 `scripts/repair_library.py`，可一键备份数据库、逐库重建索引、清理串号残留，并可用 `.nfo.bak` 恢复被写错的 NFO。

## 改进

- **分类浏览重做**：选择「按女优 / 按片商 / 按年份」后，主区域直接切换为分类浏览（默认封面卡片，可切标签列表），不再同时显示影片墙；分类数量多时分批展开。
- **统计随筛选变化**：总数 / 资料完整 / 缺资料 / 未刮削 / 刮削失败 / 文件丢失会跟随当前分类与搜索实时变化。
- **性能**：分组封面由逐个查询改为单次窗口函数查询，大库分组接口从秒级降到几十毫秒；分类视图不再请求影片墙；切换媒体库复用已加载数据。实测切换媒体库约 2 ms、单次分组请求 15–40 ms。
- **唯一 NFO**：每部影片只维护一个 NFO —— 单视频目录用 `movie.nfo`，多视频目录用 `<视频文件名>.nfo`；刮削任务会被自动配置成写同一个文件，多视频目录里的 `movie.nfo` 不再参与读写，避免多部影片互相覆盖资料。
- **刮削后自动刷新**：任务成功即用抓取结果更新索引并写回 NFO；即使媒体服务器把 NFO 改写成只含标题的 stub，卡片也不会退回「缺资料」，重新扫描同样不会清空已刮好的资料。

## 修复

- 媒体库批量刮削后索引错乱：同目录多部影片被错误合并为「一个影片 + 多个文件」，并连带写错 NFO。
- 任务成功后媒体库不刷新、卡片长期停留在「缺资料」。
- 同名 NFO 与空壳 `movie.nfo` 并存时读到了错误文件。
- 跨库统计不随分类变化、分类下拉切换后主内容不变。
- 任务卡片上的资料入口不显示（列表接口缺少关联影片字段）。
- 概览媒体墙与媒体库职责重叠。

## 升级方式

- Windows：下载本页面的 `JavSP-Web.exe`，保留原 `data` 目录即可。
- Docker：`docker pull ghcr.io/fyy656/javsp-web-next:2.1.0`（或 `:latest`）。
- 从旧版本升级后建议对媒体库执行一次「扫描」，让索引按新的 NFO 归属规则重建；升级前请备份 `data` 目录。
